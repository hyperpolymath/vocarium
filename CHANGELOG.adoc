=== [Unreleased]

==== Fixed

* *`+mise.toml+` declared `+zig = "latest+` while `+.tool-versions+` pinned
0.16.0 (2026-11-22).* The invoke-slice gate reads `+.tool-versions+` and
hard-fails on any other `+zig version+`, so a developer whose mise resolved
`+latest+` got a compiler the gate refuses (issue #46). `+mise.toml+` now pins
`+zig = "0.16.0"+`, matching `+.tool-versions+` and `+mlugg/setup-zig+` in
`+vocarium-ci.yml+`. The gate's tool-pin assert now also compares the `+zig+`
pin in `+mise.toml+` with `+.tool-versions+` and fails on disagreement, so the
drift cannot return; a missing `+zig+` line is accepted, the issue's other
permitted fix.

* *The six Hypatia criticals were a retired directory, not a defect in `+src/+`
  (2026-11-22).* The `+Hypatia neurosymbolic scan+` job counted six criticals on
  `+main+` and on the docs-only #42. Read from the artifact, they were SD024
  three times (policy files naming `+.machine_readable/6a2/+`) and SD004 three
  times (`+AGENTIC+`, `+NEUROSYM+`, `+PLAYBOOK+` still living there). The store was
  never implicated. `.machine_readable/6a2/` is now
  `.machine_readable/descriptiles/`, the layout `+standards+` mandates
  (`+0-canon/CANONICAL-NAMES.adoc+`: "never write 6a2, migrate it to
  descriptiles on sight") and that `+rsr-template-repo+`, `+trope-checker+` and
  `+hermeneia+` already use; hermeneia's own STATE records the same repair for
  the same red. All 41 referencing files moved in the same commit —
  `+Justfile+`, `+build/just/*+`, `+openssf-compliance.yml+`, the arrival-pack and
  coaptation readers, the contractiles, the policies and the docs. No
  `+.hypatia-ignore+` entry: both rules were right about what they saw.
  `+deposit-findings+` moves from `+if: always()+` to `+if: ${{ !cancelled() }}+`
  so a cancelled run no longer reddens a job that needs artifacts it will not
  find. Triage record: `+docs/reports/security/hypatia-triage-2026-11-22.adoc+`.

* *Workflow lint reads the SPDX header block and the lockfile (2026-11-17).*
The lint tested line 1 of each workflow for the SPDX identifier, but
`+gh actions-lock+` puts its own banner on line 1 whenever it refreshes the
lockfile, so the test failed on 26 of 28 workflows here and on `+main+`. It now
reads the leading comment block, the same test as `+standards+`
`+governance-reusable.yml+`; a workflow with no identifier there still fails.
The pin step required an inline commit on every action, which the move to
`+actions.lock+` made unsatisfiable (38 tag references). It now checks lockfile
coverage and keeps the inline-commit rule for reusable workflow calls, as the
copy of this lint in haec does.

* *Stack coherence: the checker pin and the scan pin (2026-11-17).* The
invoke-slice gate pins trope-checker at `+0dceab6+` (was `+4ecba4f+`), the
commit haec and hermeneia move to in the same sweep. Between the two commits
trope-checker's `+src/+`, `+schemas/+`, `+spec/+` and conformance fixtures are
unchanged. `+zig build test+` and `+tests/e2e/invoke_slice.sh+` pass at the new
pin (Zig 0.16.0, run locally). The Hypatia scan pin moves to the revision that
installs OTP 27.3.4.19 (hypatia#1061).

* *The `+proof-check-idris2+` account was wrong (2026-11-09).* Review found it,
  and it was right. `+docs/status/PROOF-STATUS.adoc+` said that with a toolchain
  present every individual `+proof-check-*+` recipe would report green on
  template boilerplate, and that only the aggregate fails, "because of comment
  text, not because it checked anything". That holds for Coq and Lean, and for
  Agda only if its standard library is configured (`+proof-check-agda+` does not
  configure it), but is false for Idris2: the recipe runs `+idris2 --check+` from
  the repository root with no `+--source-dir+` and there is no `+.ipkg+` in the
  tree, so every file under `+verification/proofs/idris2/+` declares a module name
  (`+Types+`, `+ABI.Compliance+`, …) that cannot match the name Idris2 derives
  from its path. Idris2 rejects the header before elaborating anything, and
  because `+proof-check-all+` runs its dependencies in order it would stop there
  and never reach `+proof-scan-dangerous+`. The entry now states both failure
  paths and which one applies when. NOT RUN: Idris2 is unavailable in this
  session, so the Idris2 path is read from the recipe and from Idris2's own
  header check in `+src/Idris/ProcessIdr.idr+`, not executed — and that is said
  in the document rather than left implied.

==== Fixed

* *`+docs/status/PROOF-STATUS.adoc+` published a percentage, which PROOF-POLICY
forbids (2026-11-09).* The summary read `+*Overall*: 0% proven+`. §8.4 rule 7 is
explicit — "Never publish 'X% proved', an average grade, or a single confidence
score" — and asks for a count per category with the denominator instead. The
figure was accurate; the form was the forbidden one. It now reads as a census.
The same line ships in `+rsr-template-repo+`'s `+PROOF-STATUS.adoc+`, so fixing
it there is the solution at source.
* *`+docs/status/PROOF-STATUS.adoc+` title was an unfilled mint placeholder
(2026-11-09).* Its title carried the mint's unfilled project-name token; it now reads
`+VOCARIUM+`, matching haec and hermeneia. The repository's placeholder gate
(`+.github/workflows/openssf-compliance.yml+`) checks a fixed list of required
files that does not include the status surfaces, which is why this passed CI.

==== Added

* *A note saying what `+verification/proofs/+` actually contains (2026-11-09).*
Every file there is an unmodified mint template that states nothing about
vocarium, so the 0%-proven summary is accurate rather than a backlog. The note
also records that `+build/just/proofs.just+`'s `+proof-check-*+` recipes report
`+SKIP+` and continue, against this repository's `+no-silent-skip+` constraint,
and that they are not reachable from the golden path.
* *An aftermath record and registry triage for the A2ML retirement (2026-11-22).*
`+docs/reports/deed/a2ml-retirement-triage-2026-11-22.adoc+` records what
`+1b402f9+` (#61) changed, why the deeds on `+main+` are proposals rather than
registry-confirmed facts (no `+chora-registry+` entry exists for vocarium), a
ready-to-file registration bundle, the ordered unblock path, and the residue of
the retired format. Its sibling
`+a2ml-removal-record-2026-11-22.adoc+` reconstructs, per file, the removal record
the `+1b402f9+` deletion carried out of band: 119 `+.a2ml+` files, 128,994 bytes,
with blob ids and `+sha256+` for each — all verified against `+1b402f9^+`. No
`+.a2ml+` file is deleted, renamed or reintroduced by this change; nothing is
minted or registered by it.
* *The hosted pre-commit.ci baseline was cured at its root causes (2026-11-22).*
`+.github/FUNDING.yml+` is instantiated (`+hyperpolymath+` ×3), matching the
sibling convention of `+trope-checker+` / `+trope-particularity-workbench+`.
The three unfilled Tier-C placeholders under `+container/stapeln/+`
(`+compose.toml+`, `+compose.example.toml+`, `+manifest.toml+`) were removed:
nothing at runtime reads them (`+build/just/container.just+` guards on existence),
and estate siblings either fill them (hermeneia) or never ship them (haec,
trope-checker). `+.devcontainer/devcontainer.json+` is exempt from `+check-json+`
(JSONC by the Dev Container spec; the estate ships it with comments); no other
JSON file is exempt. The ShellCheck lane is annotated at the exact findings
(comment/directive-only edits: a `+# shellcheck shell=bash+` directive in
`+.envrc+`, file-level `+disable=SC2094+` in `+.githooks/validate-k9.sh+`
(targets are read, never written), `+disable=SC2034+` for unused palette/timing
assignments and `+disable=SC2317+` for helper functions invoked indirectly in
`+tests/e2e.sh+`, `+source=/dev/null+` for the `+/etc/os-release+` read in
`+build/setup.sh+`, and `+disable=SC2016+` on the intentional literal
`+${{ }}+` grep patterns asserting workflow expressions). The EditorConfig lane
is cured by normalising leading-padding to the `+.editorconfig+` multiples
(195 lines, 30 files, down-rounding; verified whitespace-only via
`+git diff -w+` and a local multiple-of-N scan). The two lanes are pre-existing
repository-wide issues, not introduced by this change; both are now green.
