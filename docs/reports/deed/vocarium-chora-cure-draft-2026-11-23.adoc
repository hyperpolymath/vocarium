== The canon, as of 2026-11-23

Identity (the "one id" rules):

* *ADR 0008* (gv-clade-index#111): a repository id is minted once, from the
  birth path; a move changes location only; a registered repo is never removed.
* *U4 / V8 / deed.abnf v1.3.0* (standards#1473, #1475, #1479, #1481): the deed
  carries the registry's `uuid_v8` for the birth path as an opaque
  `#uuid"…"` literal. UUIDv5 of the same path stays in the registry as
  an alias and never appears in a deed. v5-in-an-identity-field is a
  strict-mode error (C10/T30). `#u5` in an identity field is an error in
  every mode (Q2). Estate, platform and federation ids are the profile-C
  UUIDv8 of their `chora:` preimages (C9, amended, owner-confirmed 2026-11-12).
* *U1* — minted once, never moves. *B1* — `:beholding-chora` is the birth
  estate, not the current org. *V1* (2026-11-12): exactly one id per deed.
* *L1* — a repo that predates V9 and was never registered is registered
  late. *Registry rename (2026-11-19, chora-registry#124)* — the
  registry is now `hyperpolymath/chora-registry`; no id is minted in the
  retired `gv-clade-index` domain; late mints mint in the `chora-registry`
  domain with `:minted-in chora-registry` (precedent: affinescript,
  `chora-registry:github.com/hyperpolymath/affinescript`,
  `0858724e-265e-81d0-909b-05cf7e1b4b2d`, chora-registry#125).

CLADE (placement):

* *clade-12 is authoritative* (owner ruling W10): `fv nl rm gv db ap ix dx pt
  ax gm sc` = Formal Verification · Nextgen Languages · Repo Management ·
  Governance & Standards · Databases · Applications · Infrastructure & Cloud ·
  Developer Ecosystem · Protocols & Interop · AI & Neurosymbolic · Games ·
  Security. The old `clade-hygiene` contractile is retired with A2ML.
* *Placement is an identity fact* in the repo's own `<repo>_chora.deed`
  `(clade …)` clause, checked against clade-12; the registry wins on any
  difference.
* *CA1* (CHORA-SPEC v0.4.9, standards#1680, 2026-11-19): `(clade …)` takes the
  registry seed's placement shape —

  (clade (placement :scheme clade-12 :category rm :primary #t)
         (placement :scheme clade-12 :category gv :rank 1))

  One primary per scheme; ranks 1..n. The flat `:primary/:secondary` form and
  `:primary-name`/`:assigned`/`:rationale` are **withdrawn**. Placements are
  copied from the registry; a chora may name only schemes and categories the
  registry declares; migration is one repo per PR with a one-release warning
  (precedent: standards#1685).
* *CLADE.deed does not exist yet* — blocked until `clade.abnf` (A7 M3) lands
  (CHORA-SPEC 11.1 rule 3; standards#1648, which asks the owner to rule
  CLADE.deed as the source of truth over `standards-map.toml`; unruled).

== Cure blueprint — post-registration PR (one repo, one PR)

Apply *after* filing, in this repository, as a single PR:

1. `vocarium_chora.deed`:
   * `:repo-uuid #u8"chora-registry:github.com/hyperpolymath/vocarium"` →
     `:repo-uuid #uuid"<id minted by the registry>"`.
   * `(clade :primary db :secondary () :rationale …)` →
     `(clade (placement :scheme clade-12 :category <primary as recorded by the registry>
     :primary #t) (placement :scheme clade-12 :category <further as recorded>
     :rank 1) …)` — copy the complete clade-12 placement set the registry holds:
     one `:primary #t`, then one `:rank n` per further category, ranks 1 to n
     with no gap; "as recorded" applies to each `:category`, not to how many
     placements there are — with the old rationale kept only as a `;;` comment
     above the clause if the owner wants the history (#1685 pattern).
   * Header comment: drop the "deterministic profile-C name, not a claim that
     a registry entry has already been minted" note; keep the truth — the id
     is registry-minted, minted once, never moves.
   * Line length stays under the 998-octet cap (longest current line: 119).
2. Four descriptiles: `:of-chora` → the same opaque `#uuid"<minted>"` id.
3. `:beholding-chora` — unchanged.
4. `CLAUDE.md` / `README.adoc` — check for `#u8`/`profile-C` mentions
   (`grep -n '#u8\|profile-C'`); update to the minted-id wording if present.
5. Verification for that PR:
   * `deed_lint.js` (standards, deed.abnf v1.3.0) on `vocarium_chora.deed`
     and the four descriptiles;
   * `scripts/check-uuid-v8.sh --strict` from a checkout of metadatastician/standards
     (the checker is not in this repository), run as
     `sh <standards>/scripts/check-uuid-v8.sh --strict <vocarium checkout>`, so it
     scans this repository and not the current directory (no `.uuid-v8-exempt`
     entry);
   * `.github/hooks/validate-deed.sh` → exit 0;
   * `.github/workflows` K9 contract validation → unchanged files still pass;
   * the CA1 one-release warning (a flat-form `(clade …)` read with a warning)
     is validator behaviour tracked separately; a note in the PR body does not
     satisfy it.
6. Explicit non-goals of the cure PR: no registry change, no id computation,
   no clade re-placement, no CLADE.deed (blocked by A7 M3 / standards#1648).
